## Goal and constraints

Let a storage owner show how ciphertext, SHA-256, Ed25519 signature, timestamps, and measured crypto timings change after editing text. Preserve every saved revision. Keep older text encrypted, owner-only, and individually verifiable. Do not add version restore, delete, retention policy, new dependencies, or attack/demo controls.

## Proposed implementation for review

- Add an immutable `record_versions` table mirroring the current record column names (`id` is the record UUID), keyed by `(id, version)` and foreign-keyed to `records(id)`.
- Store fields exactly as `records`: `id`, `owner`, `version`, nonce/ciphertext/hash/signature, three UTC times, plaintext/ciphertext/envelope byte counts, and encryption/hash/sign nanoseconds.
- Service API for tests/UI: `read_record_history(config, keys, *, owner, record_id, src_ip, session_ref)` returns newest-first `(row, plaintext)` pairs; it raises the same `RecordDenied`, `RecordMissing`, or `IntegrityError` categories as the existing read path.
- Backfill each existing current record into history as its current version exactly once, with a persistent migration marker committed atomically with the backfill. Startup must not silently recreate a missing snapshot.
- Use `schema_migrations(name TEXT PRIMARY KEY)` and marker `record_versions_v1_backfill` for the one-time migration.
- On create/edit and built-in Bob/Alice seed creation, save the new encrypted, hashed, signed snapshot in both the current row and history table in the existing transaction. Any failure rolls back both writes. Seed rows are inserted after schema initialization, so `_seed()` must add their snapshot explicitly.
- On record detail, owner-check first, then load current/history rows in one consistent SQLite read transaction. Verify each envelope/signature and decrypt on the server before returning any plaintext. Require the latest history row to match the current row; a missing/malformed latest snapshot fails the whole detail response. Show newest first, with each prior version in a collapsed section containing its plaintext, cryptographic values, UTC times, and saved timings. Existing latest-version view/edit behavior stays intact.
- If any historical version fails verification, return no record plaintext. Preserve existing signed read/accountability behavior.
- Preserve byte counts and timings with each version, but label them as measurements; they are outside the signed envelope. Do not add a hash chain or offline deletion detector.
