## Implementation

Implemented all three frozen services using the existing immediate transaction helper. Save validates without changing text, checks ownership and existing integrity inside the transaction, increments the locked version, writes only the latest sealed row, and signs the save event before commit. Read returns unchanged evidence plus verified plaintext and signs a read event. Listing verifies owned rows and releases summaries only after verification succeeds.

Expected missing/denied/integrity errors are held until after the transaction context exits. Denial/integrity events therefore commit before the service raises its generic exception; missing IDs produce no foreign-denial event. Unexpected seal/write/audit failures propagate through the transaction helper and roll back the record and success event together. Signed record-service outcomes use their matching event kind; destination context is the configured storage IP/port. No plaintext enters the audit payload.
