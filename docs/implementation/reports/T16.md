IDs end in 01/02; titles are Bob's record/Alice's record. Use seal_record for encrypted seed rows because save_record treats any supplied non-null ID as an edit and refuses a missing ID. Do not invent synthetic logged-in sessions or hardcode keys.
- Serve atomically claims data_dir/server.pid before initialization/binding; JSON contains pid and started_at_us. Exclusive publication must never replace an existing marker. Any existing marker, including malformed JSON or a link, refuses serve/reset; message instructs inspection of recorded process and manual removal only after verifying staleness. No PID probing/killing or automatic stale recovery. Release only the owned unchanged marker.

Reject root/repository/ancestors, protected checkout source/test/docs/.git subtrees and read-only sibling Project. - Create two separate storage/console app factories with existing distinct persisted session secrets. Construct two threaded make_server HTTPS listeners with the same validated certificate tuple and their configured distinct ports. Initialize before listener threads. No debugger/reloader.
- Construct/start CaptureWorker only when an interface is configured. With no interface, publish degraded capture health directly so the console explains the missing configuration while storage remains available. Missing default TShark remains capture degradation.
- Track only created listeners and started loops. On interrupt/error, stop owned capture, shutdown started active loops from the controller thread, join, and close every owned listener including a partially bound startup. Never shutdown an unstarted loop (socketserver deadlocks). Do not remove the marker if cleanup leaves live owned resources.
